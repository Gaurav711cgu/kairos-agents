# Setup, API and operating guide

## Run one mode at a time

Use Python 3.12 and Node.js 24. Recorded mode requires neither Docker nor credentials:

```bash
python3 -m scripts.reviewer demo
```

The local reviewer listens at http://127.0.0.1:3310. First dependency installation and builds take additional time. To switch modes, stop owned services first:

```bash
python3 -m scripts.reviewer stop
python3 -m scripts.reviewer fullstack
```

Full-stack setup uses PostgreSQL 55434, Keycloak 8090, FastAPI 8310 and website 3310. It generates private synthetic credentials under ignored `.runtime/reviewer005`. Read that local credential file to use the appropriate role; do not copy it into documentation, screenshots or a repository.

The default full stack starts the real control plane with inference off. A new repair additionally needs a registered qualified case, verified original source, its reviewed verification image, pinned local inference and a worker. The UI does not accept arbitrary repository URLs or source paths. A queued receipt alone is not a repair result.

```bash
python3 -m scripts.reviewer repair
python3 -m scripts.reviewer check --recorded-only
python3 -m scripts.reviewer check --fullstack
python3 -m scripts.reviewer stop
```

Repair reproduces the original saved Django10914 patch under a separate build007-reviewer tag, reporting rebuilt-image differences. Checks install locked dependencies, record actual results and list skipped probes. Recorded-only checks keep Docker off; full-stack checks add actual PostgreSQL/OIDC. Shutdown matches process identity and container ownership and preserves volumes/images. Stop Docker Desktop after required container work on the current Mac.

## Live repair execution

The default full-stack command provisions authenticated services without loading a model. On a machine with the prepared pinned model and source cache, enable the real worker explicitly:

```bash
python3 -m scripts.reviewer stop
python3 -m scripts.reviewer fullstack \
  --runtime .runtime/live-showcase008 \
  --with-inference \
  --model-cache .runtime/investigations \
  --session-seconds 900
```

Use the private generated local account in `.runtime/live-showcase008/identity.local.json`. In **Workbench**, select the registered development case `django__django-11066`, select **Tool loop · Checked revisions**, and choose **Queue investigation**. The timeline records real source/context, model responses, proposed edits and independent checks. The actual browser demonstration completed with two model calls, one candidate and four passing tests; its [receipt](../../evidence/docs008/live-execution/receipt.json) is separate from the frozen evaluation.

The opt-in command installs the locked reviewer interpreter, checks the platform, model/runtime hashes, prepared development source and storage before starting Docker, and verifies the already prepared verifier image. It reuses weights without downloads. API and worker use the same pinned model manifest. The pinned runtime supports macOS ARM64. A missing cache is an explicit setup error; the recorded viewer remains independently usable.

The session ends after 900 seconds by default. Matching repeated commands reuse the original session deadline; changed model profile/cache/case-root settings are rejected. You can stop it earlier:

```bash
python3 -m scripts.reviewer stop --runtime .runtime/live-showcase008
```

Shutdown targets owned model, worker, API, website and containers, and preserves volumes and captures. It does not quit Docker Desktop; after container acceptance on the current Mac, Docker Desktop is stopped separately. For a separate prepared source root, use `--case-root`; for the other pinned existing profile, use `--model-profile qwen3`. This is interactive execution on an exposed development case, not a rerun of the locked evaluation.


## Configuration and authority

| Setting | Purpose |
| --- | --- |
| `KAIROS_EVIDENCE_MODE=recorded` | Serve validated published captures; disable private commands and sign-in |
| `KAIROS_EVIDENCE_MODE=live` | Use the real API; unavailable API remains an explicit error |
| `DATABASE_URL` | Private restricted runtime connection |
| `KAIROS_MIGRATION_DATABASE_URL` | Private owner/setup connection; never supply it to the application runtime |
| `KAIROS_BLOB_DIR` | Local digest-addressed artifact directory |
| `KAIROS_INVESTIGATION_ROOT` | Prepared case source and verification root |
| `KAIROS_INVESTIGATION_MODEL_MANIFEST` | Explicit pinned runtime profile for model execution |
| `KAIROS_INVESTIGATION_MODEL_URL` | Trusted loopback local inference endpoint |

OIDC issuer/client/callback and origin settings are generated by reviewer setup. Authenticated actions require explicit tenant membership. Viewer reads; operator may submit/cancel/fork; administrator may publish. New records are private. Runtime roles cannot create schema or write the migration ledger.

## Explicit migrations

Set the owner connection privately, then use:

```bash
python3 -m scripts.migrate status
python3 -m scripts.migrate apply
python3 -m scripts.migrate apply --backfill
```

`status` reads only. `apply` serializes migrators and applies each checksummed revision transactionally. `--backfill` performs resumable missing-value operations after schema migration. Startup verifies the applied head and catalog; it never performs setup implicitly. Rehearse on a restored database, preserve backups and do not invent a destructive downgrade. [Migration rehearsal](../../evidence/build007/adoption-restoration.json).

## Browser routes and API routes

The browser uses Next.js proxies at `/api/public-investigations` and `/api/workbench/investigations`. The table below describes the underlying FastAPI endpoints at port 8310. Proxy names are intentionally distinct from API-server paths.

| FastAPI endpoint | Method | Authority and result |
| --- | --- | --- |
| `/api/investigations/cases` | GET | Authenticated tenant; registered case definitions |
| `/api/investigations` | GET | Authenticated tenant; paginated summaries |
| `/api/investigations` | POST | Operator/admin; durable receipt, HTTP 202 |
| `/api/investigations/{id}` | GET | Tenant-scoped source/configuration, steps, artifacts and outcome |
| `/api/investigations/{id}/progress` | GET | Tenant-scoped phase/counters/latest sequence/update time without artifact bodies |
| `/api/investigations/{id}/cancel` | POST | Operator/admin; cancellation fences later commits |
| `/api/investigations/{id}/fork` | POST | Operator/admin; fresh linked attempt and HTTP 202 |
| `/api/investigations/{id}/replay` | GET | Tenant-scoped captured playback; zero tool/model execution |
| `/api/investigations/{id}/publish` | POST | Admin; make a private record publicly inspectable |
| `/api/investigations/{id}/bundle` | GET | Tenant-scoped integrity-checked evidence download |
| `/api/investigations/{id}/patch` | GET | Tenant-scoped accepted candidate download or explicit unavailable result |
| `/api/public/investigations` | GET | Published summaries only |
| `/api/public/investigations/{id}` | GET | Published record only |
| `/api/public/investigations/{id}/bundle` | GET | Published integrity-checked evidence download |
| `/api/public/investigations/{id}/patch` | GET | Published accepted candidate download |

List pagination defaults to 25 and allows at most 100 records. Cursors use stable creation-time/ID ordering and are scoped to the listing authority.

Create and fork require a stable `Idempotency-Key`. An explicit create body is:

```json
{
  "task_id": "kairos-clock-lease",
  "configuration": "loop-v7"
}
```

This is a request example, not a fabricated response. The task must exist in the current registry. The current UI chooses v7; the backward-compatible API default remains v3, so API callers should specify a configuration. The server returns the committed investigation ID/status; that receipt does not claim that checks passed.

| HTTP result | Meaning |
| --- | --- |
| 400 | Missing or malformed `Idempotency-Key` command identity header |
| 401 | Missing or invalid authentication |
| 403 | Insufficient role or forbidden browser mutation |
| 404 | Record/patch unavailable to this authority |
| 409 | Conflicting command identity or capture-integrity conflict |
| 413 | HTTP body exceeds the bounded middleware limit |
| 422 | Invalid configuration, cursor, limits or request schema |
| 429 | Tenant/global queue admission limit reached |
| 503 | Unavailable database/upstream service or bounded resource failure |

Never retry an uncertain model dispatch merely because an HTTP/database operation failed. Identical command retries and model redispatch are different operations.

## Troubleshooting

| Symptom | Expected interpretation and action |
| --- | --- |
| Port occupied | Setup preserves the resource. Inspect ownership or stop the corresponding reviewer mode; do not kill unrelated processes. |
| Workbench shows local setup | The evidence viewer directs you to setup. Start fullstack for authenticated commands, or fullstack --with-inference with the prepared cache for model execution. |
| Investigation remains queued | Inference/worker is off by default. Prepare the qualified case, pinned profile and worker before expecting execution. |
| Pending command after lost acknowledgement | Retry with its saved identity. A changed payload requires a new intentional command. |
| Unknown dispatch | Inspect the captured intent and available response. Do not resend automatically. |
| Schema pending or drift detected | Use private setup credentials to inspect/apply the required version; do not run DDL from application startup. |
| Missing/corrupt capture | Explicit error is expected. Restore genuine bytes from the preserved package; do not manufacture replacement evidence. |
| Check fails or patch is rejected | Inspect source handles, ranges, syntax and test output. Failed verification is an observed outcome, not necessarily an infrastructure failure. |
| Docker heat | Use recorded mode for review. Run container phases sequentially and stop owned services/Desktop afterward. |
