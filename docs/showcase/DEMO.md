# Five-minute reviewer demonstration

1. **0:00 — Open the product.** Run `python3 -m scripts.reviewer demo`. Explain that the evidence viewer opens real completed captures, while Workbench provides live setup.
2. **0:30 — Show the defect.** Open the featured Django development investigation. Point to issue, pinned revision, original source and the development label.
3. **1:15 — Inspect the candidate.** Compare highlighted before/after lines. Explain that source handles and digests bind proposed edits to captured original source.
4. **2:00 — Read the tests.** Open captured output and the verifier completion result. This case has four tests. Keep the original 110-test reproduction separate.
5. **2:45 — Review the trace and cost.** Open context selection and the paired saved strategies. Show calls/tokens/timing with actual outcomes. The fresh evaluation remains 0/10.
6. **3:30 — Explain durable execution.** Show Engineering: command receipt before202, database-clock leases and fencing, captured dispatch recovery, replay without execution, and isolated patches.
7. **4:15 — Inspect measured capacity.** Show435270 localrequests, soakACKp95275.19 ms and original failed run. State that inference and OIDC throughput were excluded.
8. **4:45 — Show reproducibility.** Download evidence/patch and open Docs. Point to the explicit live command and actual browser-run receipt: two model calls, one candidate, four passing tests.

For an actual live demonstration, prepare the session before the interview using the documented model cache and local generated account. The interactive run can be inspected afterward through the authenticated workbench without rerunning inference. Keep model/containers off during unrelated review and stop owned services afterward.

The strongest defensible SDE story is reliability around model uncertainty, tested user interactions, explicit resource limits and reproducible evidence. Claims expand with their receipts, rather than with UI polish.
