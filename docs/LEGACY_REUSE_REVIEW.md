# Legacy prototype reuse review

Reviewed on 2026-10-11. The actual checkout is `/Users/gauravkumarnayak/Desktop/new-karos`; `/Users/gauravkumarnayak/Desktop/resume/new-karos` links to it. No separate `karos-new` directory was found directly under Desktop or resume. This review covers the older `harness/`, `engine/`, `ingest/` and `storage/` directories in that checkout. They remain outside the current product execution path.

## Useful foundations

- `harness/events.py` defines typed native events and chains their hashes. This is useful for local consistency inspection, provided the verifier also binds run identity and sequence. It does not make administrator-controlled history immutable.
- `harness/context.py` makes context selection observable and computes a deterministic context fingerprint. The current product preserves exact selected and omitted blocks and their source snapshots rather than relying on aggregate compaction counts.
- `harness/verifier.py` separates deterministic verification from the model. The current order workflow retains independent full-source grading and deterministic money arithmetic.
- `ingest/storage.go` writes inserted steps and outbox entries in one SQLite transaction. It returns success only after `tx.Commit()`. The transaction boundary is worth retaining; a separate ingest service is not required for the current local workload.
- `engine/stats.py` uses paired score differences and seeded resampling. That can support exploratory interval plots. It is insufficient as the product's safe-release rule.

## Verified defects and limits

| Legacy area | Finding | Current decision |
| --- | --- | --- |
| SQL tool permission | `SqlExecutionTool.run` splits text on whitespace to detect destructive keywords. `DELETE/**/FROM example` bypasses the check and deletes rows. Reproduced against an in-memory disposable SQLite table; remaining row count was zero. | Do not expose this tool. Any future SQL integration must use database read-only permissions, read-only transactions, statement restrictions and resource limits. Text filtering is not an authorization boundary. |
| Replay comparison | `ReplayEngine.detect_divergence` includes `MODEL_INVOKED` among relevant events but never compares its payload. Two different final model responses at the same step return `diverged=False` and the description claims a bitwise match. Reproduced with two synthetic in-memory logs. | Current recorded playback returns the captured request, response and result without network calls. It verifies event and object bindings; it does not claim a new model run will reproduce the same output. |
| Checkpoint recovery | `AgentHarness.run` reconstructs only system/task context on resume. Prior tool observations, model conversation state and durable tool-result receipts are absent. It restores executed argument keys but substitutes a placeholder cache-hit output. Checkpoint events are only in process memory unless a separate caller persists them. | Current jobs persist dispatch intent and response checkpoints in PostgreSQL, fence worker ownership, and explicitly distinguish unknown provider outcomes. Only captured known results may continue; arbitrary historical-step continuation remains unsupported. |
| Tool idempotency | Legacy argument hashes do not bind tenant, target state or durable external receipts. Failed executions are also added to the in-memory executed-key set. Forking into a new run can append old run-bound events without rebinding their identity. | Current sandbox approvals bind source result and proposal digests; sandbox effects use transactional receipts. Replay and fresh forks do not inherit approval or execute effects. |
| Go ingest acknowledgement | `RingBuffer.Push` is memory-only. The current HTTP handler does call `StoreBatch` and waits for its commit before returning 200, so describing every current HTTP acknowledgement as memory-only would be inaccurate. However, concurrent requests share push/drain operations, response counts describe whatever was drained rather than exact request events, dropped entries still allow `status: ok`, and popped events are not retained after storage failure. There are no per-event durable receipts. | Current API acknowledges the committed command and stable identifier directly from PostgreSQL. A future Go ingest path needs request-bound receipts, replayable durable staging and explicit overflow/error semantics before it can claim durable capture. |
| Duplicate ingestion | SQLite `ON CONFLICT(run_id, seq_id) DO NOTHING` treats a changed payload with an existing key as a duplicate. The ingest service does not validate the supplied event hash chain. | Current command keys bind a digest and conflicting retries return 409. Current job reads verify local sequence, run identity, event continuity and captured-object bindings. |
| Buffer description | `RingBuffer` uses a `sync.Mutex`; the old README calls it lock-free. | Retain honest implementation descriptions and measure before adding a performance-oriented service. |
| PostgreSQL schema | `storage/schema.sql` partitions `steps` by `created_at` but declares `PRIMARY KEY(run_id, seq_id)`. PostgreSQL requires partitioned-table unique constraints to include the partition key. This schema cannot establish its advertised primary key as written. It also predefines only October 2026's partition. | Current product uses its tested additive `kairos_api/schema*.sql` migrations. Partitioning is deferred until measured volume and retention requirements justify its additional constraints. |
| Statistical release gate | `is_regression=False` means the exploratory test did not detect a regression. It does not establish noninferiority. Three samples are permitted, repeats are not grouped by independent task family, no predeclared acceptable loss is enforced, and the bootstrap sign proportion is labeled a p-value without calibration evidence. | Use the current three-way PASS/FAIL/INCONCLUSIVE gate with predeclared margin, independent sampling unit, minimum evidence and hard invariant blockers. Calibration simulations remain separately labeled from model performance. |
| Context budget | Legacy character-count token estimates and summary truncation can still leave selected context above the configured token budget. `compactor_policy` primarily labels the same hardcoded procedure. | Current offline model service tokenizes the rendered request and enforces its input ceiling. Context policies have explicit inclusion decisions and independent grading. |

## Reuse boundary

Reuse the ideas and test cases, not the prototype's guarantees. No legacy code was promoted into the current production path during this review. The SQL and replay reproductions used disposable local objects and made no external calls. PostgreSQL schema incompatibility above is a source-level finding; the obsolete schema was not applied to the working database.

The current system still makes narrower claims than a general agent platform: local synthetic order cases, one captured model dispatch per job, explicit unknown outcomes, network-free recorded playback and controlled sandbox effects. Local hashes remain consistency evidence, not independent immutable attestations. Customer adoption and public deployment require separate evidence.
