# Kairos completion contract

## Objective and fixed constraints

Deliver an interview-ready local investigation system with reproducible backend behavior and an empirically tested repair workflow. Preserve all frozen studies, trained weights and negative outcomes. Zero spend, existing Mac/free Colab, 6 GiB local experiment storage and 4 GiB reserve. No paid fallback, hidden test leakage, retrospective evaluation tuning or manufactured repair. A phase advances only after its executable gates pass. A failed gate requires diagnosis and a regression check, not a renamed success.

## Phase 1 — establish causes, not another training run (active)

Audit actual training examples, assistant targets, token masking and source-handle replay against the inference interface. Classify every observed failure by source localization, transport/schema, authority/range, syntax, behavior and environment. Keep the completed nine-case study locked. Gate: every output has a reproducible classification; training/evaluation interface differences have exact examples and source locations; proposed fixes have development-only regressions. Do not download model weights or start training in this phase.

## Phase 2 — repair mechanics and backend regression

Use existing validators and bounded loop. Resolve confirmed interface defects with the smallest versioned change. Keep original-source authority, allowed paths, syntax validation, immediate independent test feedback, durable captures, fencing and uncertain-dispatch refusal. Gate: malicious/stale edits still rejected; known development failures reproduce then pass targeted tests; no changed historical behavior without a configuration version. A software test does not establish model repair success.

## Phase 3 — verified training admission and model sanity

Use a development-only set with independently reproduced baseline/reference results and exact target replay. Audit deduplication and split ownership. Before full training, demonstrate that the exact training serialization can learn a tiny admitted batch and reproduce valid source-bound edits. Then check distinct development examples. Gate: actual generated edits apply and pass independent checks on the sanity batch; record model memory/checkpoint/export behavior. Colab upload of changed files still requires the applicable browser permission. No claim that 100 rows are 100 independently verified repairs.

## Phase 4 — bounded model experiment

Freeze candidate protocol, profile, prompts, verifier and untouched case identities before execution. Compare the same base and adapter under equal strategy/budget settings, retaining every attempt and resource failure. Gate: full generation and independent repair-check captures; a positive model claim requires observed improvement, not lower training loss. A missed quality target remains an open model gate; never tune on the completed evaluation020 cohort.

## Phase 5 — product and release acceptance

Run backend and frontend checks after final code changes, then recorded/live user journeys, mobile/keyboard/download checks, clean reviewer reproduction and evidence manifests. Reuse prior capacity measurements only if their execution code is unchanged. Gate: no failing required acceptance check; skips and environment scope explicit. Keep Docker off except required checks. Audit all README/site claims against receipts; public hosting remains separate.

## Phase 6 — interview handoff

Provide a working reproduction command, five-minute demonstration, architecture/request path, failure/recovery explanation and claim-to-receipt table. Explain model training separately from repair performance. Gate: reviewer can inspect real patches, test output, durable commands and measured limits. No production-scale, leadership or model-superiority claim without corresponding evidence.
